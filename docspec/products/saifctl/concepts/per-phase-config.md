id: per-phase-config
explains: how phases customise their own gate, agent, container, runner, and limits without affecting the rest of the run; and what it costs to change each setting per phase
learning_outcomes:
  - 'Each phase can override most run-level settings via `phase.yml` (file form), or via inline override at `feature.yml.phases.phases.<id>`. Phase-defaults live at `feature.yml.phases.defaults`; uniform settings live at `feature.yml` top-level.'
  - 'Settings are grouped: `gate.*` (script + retries), `agent.*` (profile, install, env, model, base-url, secrets, reviewer), `container.*` (startup, cedar, no-leash, image, sandbox-profile, engine, compose-file), `runner.*` (test profile/image/script, stage script, resolve-ambiguity, test-retries), `limits.*` (max-attempts).'
  - 'Resolution: `phase.yml` > `feature.yml.phases.phases.<id>` > `feature.yml.phases.defaults` > `feature.yml` (top-level) > `saifctl/config.*` > built-in. Object values resolve sub-key by sub-key; lists replace at the most-specific declaring layer.'
  - 'Cost-of-change is graded by lifecycle level. Level 1 (`gate.*`, `agent.script`) rewrites a file in the live container — free per round. Level 1.5 (`agent.env`, `agent.model`, `agent.base-url`, `agent.secrets`, `agent.reviewer`) rewrites a small env file the container sources each round — no restart. Level 2 (`agent.profile`, `agent.install`, `container.startup` / `cedar` / `no-leash`) tears down the coder container and rebuilds it against the same sandbox dir — ~10–30s. Level 3 (`container.image` / `sandbox-profile` / `engine` / `compose-file`) does the Level-2 restart on top of an image pull / engine swap / compose-stack swap — minutes on first pull. Level 4 (`runner.*`, `tests.none`) is test-runner routing only — free per attempt. Loop state (`limits.max-attempts`) is a per-phase outer-attempt cap, distinct from the run-level `--max-runs`.'
  - "`tests.none: true` declares 'this phase has no own tests'; the test runner is bypassed for that phase. Feature/project tests still gate at the run's last phase, so end-state contracts always run somewhere."
  - 'Preview the resolved config per subtask with `saifctl feat phases compile <feature>` before invoking `feat run`. The pre-flight `--strict` validator catches lockstep mistakes (e.g. `container.cedar` set with `container.no-leash: true`) and previews adjacent-phase Level-2/3 cost.'
analogies:
  - Like nginx site-include directives — most settings inherit, individual sites override
  - Per-phase costs are like compile-time vs link-time vs runtime — cheaper the closer to runtime
  - 'The phase boundary is a controlled restart, not a fresh process: the sandbox dir survives like a paused tmux session'
